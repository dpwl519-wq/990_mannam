# 990 인연 · 직장인 소개팅 (Supabase 연동판 v2.0)

## v2.0에서 달라진 것

- **회원가입** — 닉네임이 `따뜻한 라떼`처럼 자동으로 채워지고 옆의 ↻ 버튼으로 다시 뽑을 수 있어요. 출생연도는 **1980~2004년** 콤보박스.
- **운영자 전용 입장** — 로그인 화면 맨 아래 `운영자로 들어가기` → 운영자 이메일·비밀번호·PIN(`990418`)만으로 소개팅 프로필 없이 콘솔로 들어갑니다. 계정이 없으면 `운영자 계정 만들기`.
- **프로필 등록 필수** — 사진 1장과 모든 항목(닉네임·나이·직업·회사·지역·MBTI·키·한 줄 소개)을 채워야 다른 화면이 열립니다. 빠진 항목은 화면 위 배너에 표시돼요.
- **나이 표기** — 카드·프로필에 `1991년(만35세)` 형식으로 표시하고 글자를 키웠습니다.
- **매칭 우선순위** — 외모 · 직장 · 키 · 나이 · MBTI·성격 · 동네·거리 · 취미·가치관 · 비흡연·음주 중 3개까지.
- **지역** — 활동 지역은 `시·도` + `구·시·군` 콤보박스(예: `서울 강남구`), 선호 지역은 같은 콤보박스로 **최대 3곳**까지 추가·삭제.
- **지인 번호 차단** — `연락처에서 불러오기`(Android Chrome) · `연락처 파일(.vcf)` · 직접 입력. 번호는 기기 안에서 해시로 바뀌어 저장됩니다.
- **키 인증(선택)** — 건강검진 결과표·신체검사서 사진을 올리면 운영자 확인 후 프로필에 `키 인증` 뱃지.
  직장인 인증(`profiles.verified`)과 **별개의 값**(`profiles.height_verified`)이라 둘 다 승인되면 카드·상세·매칭 목록·내 프로필에 두 뱃지가 나란히 붙습니다.
- **디자인** — 가짜 상태바(시간·배터리)를 없애고, 본문 14px / 설명 13.5px / 캡션 12px · 카드 여백 14px 16px · 목록 행 12px 0 으로 간격을 통일했습니다.

`index.html` 한 파일로 도는 모바일 웹 앱입니다. 데이터는 **Supabase**(인증·프로필·호감·매칭·대화·인증심사·충전·신고)에 저장됩니다.

## 1. 처음 한 번만 — Supabase 준비

1. **스키마 실행** — Supabase 대시보드 → SQL Editor → New query →
   `supabase_schema.sql` **전체**를 붙여넣고 **RUN** (여러 번 실행해도 안전합니다).
   테이블 9개 + 운영 설정, RLS 정책, 서버 함수, 데모 프로필 6명이 만들어집니다.
2. **이메일 인증 끄기(권장)** — Authentication → Sign In / Providers → Email →
   *Confirm email* **OFF**. 끄면 가입 즉시 로그인됩니다.
   켜 둔 경우: Authentication → URL Configuration → **Site URL** 을
   `https://dpwl519-wq.github.io/990_mannam/` 로 바꾸고, 가입 후 메일의 인증 링크를 눌러야 로그인됩니다.
3. **운영자 PIN** — 기본값 `990418` (`admin_config` 테이블). 바꾸려면:
   ```sql
   update public.admin_config set admin_pin = '내PIN' where id = 1;
   ```
4. **입금 계좌** — 앱 → 운영자 → PIN 입력 → `입금 계좌 설정` 탭에서 저장하면
   사용자 충전 화면에 바로 표시됩니다.

## 2. 사용 흐름

1. 앱에서 회원가입(이메일·비밀번호·닉네임·성별·출생연도) → 매칭권 3장 지급
   - 닉네임은 `따뜻한 라떼`처럼 자동 제안되고, 옆의 ↻ 버튼으로 다시 뽑거나 직접 고칠 수 있어요.
   - 출생연도는 **1980~2004년** 콤보박스에서 고르고, 저장되는 `age`는 기존 프로필과 같게 `올해 − 출생연도`예요.
2. 첫 로그인 때 **프로필 등록** 화면으로 바로 이동합니다.
   사진 1장과 모든 항목(닉네임·나이·직업·회사·지역·MBTI·키·한 줄 소개)을 채워 저장해야
   다른 화면(오늘의 인연·매칭·대화)이 열립니다. 빠진 항목은 화면 위 배너에 표시돼요.
3. 첫 로그인 때 **데모 인연**이 자동으로 채워집니다
   (받은 호감 2 · 매칭된 대화 1 · 심사 대기 인증 2 · 충전 요청 1 · 신고 1).
   실제 가입자가 늘면 프로필 → `데모 인연 함께 보기`를 꺼 두세요.
4. 운영자 콘솔(PIN)에서 인증 승인 · 입금 확인(매칭권 지급) · 신고 정지를 처리합니다.
   - 로그인 화면 맨 아래 **운영자로 들어가기** → 운영자 이메일·비밀번호·PIN(`990418`)을 넣으면
     소개팅 프로필 없이 바로 운영자 콘솔이 열립니다. 계정이 없으면 **운영자 계정 만들기**로
     운영자 전용 계정을 만들 수 있어요(성별을 고르지 않아 인연 덱에는 나오지 않습니다).

## 3. 구조

| 파일 | 역할 |
| --- | --- |
| `index.html` | 화면 + 앱 로직 (Supabase JS v2 CDN, publishable 키만 사용) |
| `supabase_schema.sql` | 테이블 · RLS · 서버 함수 · 데모 시드 (idempotent) |

- 매칭권 차감·48시간 자동 반환·매칭 성사·후기 300P·충전 승인은 모두 **서버 함수**(`send_like`, `expire_likes`, `submit_review`, `admin_review_charge` …)에서 원자적으로 처리됩니다.
- 매칭 우선순위는 **외모 · 직장 · 키 · 나이 · MBTI·성격 · 동네·거리 · 취미·가치관 · 비흡연·음주** 중 3개까지 고를 수 있어요(외모는 사진을 올린 프로필, 키는 178cm 이상, 나이는 선호 나이 기준).
- 지인 번호 차단은 **연락처에서 불러오기(Android Chrome)** · **.vcf 파일 올리기** · 직접 입력을 지원하고, 번호는 기기 안에서 해시로 바뀌어 저장됩니다(이름·원본 번호는 저장하지 않음).
- 앱에서 직접 바꿀 수 있는 프로필 열은 열 단위 권한으로 제한했습니다
  (`match_tickets`, `points`, `verified`, `height_verified`, `is_admin` 등은 앱에서 위조 불가).
- `email`, 차단 목록, 관리자 여부는 다른 사용자에게 노출되지 않습니다.
- 새 메시지·호감은 7초 주기로 다시 읽어 옵니다.

## 5. 참고

- 결제는 **계좌이체/카카오페이 입금 확인형**입니다(자동 결제 아님). 회원이 입금자명을 남기면 운영자가 확인 후 매칭권을 지급합니다.
- 회사 메일 인증은 아직 화면 인증번호 방식이며 실제 메일 발송은 연결되어 있지 않습니다. 서류 인증은 운영자 심사로 처리됩니다.
- 전화번호 차단은 해시 값만 저장하고 원본은 남기지 않습니다.
