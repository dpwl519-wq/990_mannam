# 990 인연 · 직장인 소개팅 (Supabase 연동판 v2.0)

## v2.0에서 달라진 것

- **회원가입** — 닉네임이 `따뜻한 라떼`처럼 자동으로 채워지고 옆의 ↻ 버튼으로 다시 뽑을 수 있어요. 출생연도는 **1980~2004년** 콤보박스.
- **운영자 전용 입장** — 로그인 화면 맨 아래 `운영자로 들어가기` → 운영자 이메일·비밀번호·PIN(`990418`)만으로 소개팅 프로필 없이 콘솔로 들어갑니다. 계정이 없으면 `운영자 계정 만들기`.
- **가입 대기 · 운영자 승인** — 새로 가입하면 바로 입장하지 않고 `가입 승인 대기 중` 화면이 뜹니다. 운영자 콘솔 → `가입 승인` 탭에서 승인해야 앱(오늘의 인연·매칭·대화·프로필)이 열립니다. 승인 전에는 다른 회원의 추천에도 나오지 않아요. (켜는 방법: `supabase_signup_approval.sql` 한 번 실행)
- **프로필 등록 필수** — 사진 1장과 필수 항목(닉네임·나이·직업·지역·MBTI·키·한 줄 소개)을 채워야 다른 화면이 열립니다. 빠진 항목은 화면 위 배너에 표시돼요.
- **회사 · 인증 키는 직접 입력 불가** — 회사 칸은 옆의 `인증` 버튼(회사 메일 · 명함·재직증명서)으로만 채워지고, 키는 입력할 수 있지만 `키 인증`이 승인되면 그 값으로 잠깁니다.
- **나이 표기** — 카드·프로필에 `1991년(만35세)` 형식으로 표시하고 글자를 키웠습니다.
- **매칭 우선순위** — 외모 · 직장 · 키 · 나이 · MBTI·성격 · 동네·거리 · 취미·가치관 · 비흡연·음주 중 3개까지. 라벨 옆 `초기화`로 고른 1·2·3순위를 한 번에 비울 수 있어요.
- **수락 · 거절 사유 팝업** — 오늘의 인연에서 `호감 보내기`·`건너뛰기`, 받은 호감에서 `수락`·`거절`을 누르면 같은 8개 항목 중 이유를 고르는 팝업이 뜹니다(여러 개 선택 · 최소 1개). 고른 이유가 쌓여 내 취향 순위가 스스로 바뀝니다.
- **990 인연이 관리 중인 내 취향 순위** — 내 프로필에서 현재 1·2·3순위와 항목별 점수·응답 건수를 보고, `취향 데이터 초기화`·`수동 순위 다시 고르기`로 시작점을 바꿀 수 있어요. 이 순위가 오늘의 인연 카드 순서·추천 배지에 그대로 쓰입니다.
- **상대의 우선순위 표시** — 카드·상세 프로필·받은 호감 목록에 `이분이 중요하게 보는 순위 1. 직장 · 2. 키 · 3. 취미·가치관` 처럼 표시합니다(실회원은 본인이 저장한 값, 데모 6명은 화면 확인용 예시 값).
- **지역** — 활동 지역은 `시·도` + `구·시·군` 콤보박스(예: `서울시 강남구` · `경기도 성남시`), 선호 지역은 같은 콤보박스로 **최대 3곳**까지 추가·삭제. 선호 지역의 구·시·군에는 **`전체`**가 있어 `서울시 전체` · `경기도 전체`처럼 시·도 단위로도 고를 수 있어요(같은 시·도의 `전체`와 구 선택은 서로 갈아 끼워집니다).
- **지인 번호 차단** — `연락처에서 불러오기`(Android Chrome) · 번호 직접 입력. 번호는 기기 안에서 해시로 바뀌어 저장됩니다.
- **키 인증(선택)** — 건강검진 결과표·신체검사서 사진과 키를 올리면 운영자 확인 후 프로필에 `키 인증` 뱃지. 승인된 키는 그 값으로 잠깁니다.
  직장인 인증(`profiles.verified`)과 **별개의 값**(`profiles.height_verified`)이라 둘 다 승인되면 카드·상세·매칭 목록·내 프로필에 두 뱃지가 나란히 붙습니다.
- **데모 회원 노출** — 회원 화면에서는 빠지고, 운영자 콘솔 → `설정` → **데모 회원 노출**에서 모든 회원 대상으로 켜고 끕니다.
- **디자인** — 가짜 상태바(시간·배터리)를 없애고, 본문 14px / 설명 13.5px / 캡션 12px · 카드 여백 14px 16px · 목록 행 12px 0 으로 간격을 통일했습니다.
- **오늘의 인연 카드** — 태그·뱃지를 걷어 낸 미니멀 에디토리얼 카드(이름·나이·직업·지역·MBTI·한 줄 소개)만 보여 주고, 카드를 누르면 상세 프로필 시트에서 사진(워터마크·저장 방지 적용, 데모는 비공개 자리 표시), 취미·가치관, 상대의 우선순위, 추천 근거, `이 프로필 신고하기`를 봅니다.
  - **긴 자기소개** — 카드에서는 4줄까지만 보여 주고 줄 경계에서 `…`로 끊은 뒤 `소개 더보기` 버튼을 띄웁니다(글자 중간에서 잘리거나 구분선과 겹치지 않게, 4줄에 들어가는 길이를 화면에서 직접 계산). 상세 프로필 시트에서는 줄바꿈을 살려 **전문**을 보여 줍니다.
  - **아이폰 Safari 카드 잘림** — 카드 높이를 화면에 맞춰 고정하지 않고 내용만큼 자연스럽게 커지도록 했습니다. 그래서 주소창·툴바 때문에 화면이 낮아져도 이름·직업·소개가 찌그러지지 않고, 내용이 길면 `오늘` 화면이 아래로 스크롤됩니다.
- **하루 두 장 · 두 번 다시 안 뜨는 인연** — 오늘의 인연 두 장은 **Supabase(`today_deck()` 함수)**가 정합니다(기기를 바꾸거나 브라우저를 지워도 같은 두 분, 하루 두 장을 넘지 않음). `건너뛰기`·`호감 보내기`·`매칭`·`차단`·`신고`한 상대는 `seen_targets` 표에 **영구히** 남아 다음 날은 물론 다른 기기에서도 다시 추천되지 않아요. `직전 건너뛰기 취소`를 누르면 그 카드만 오늘 안에서 다시 돌아옵니다.
  - 화면 위 `오늘의 인연 1 / 2` 표시로 진행을 보여 주고, 두 장을 모두 확인하면 세 번째 카드 없이 `오늘의 인연 2명을 모두 확인했어요` 안내로 끝납니다.
  - 켜는 방법: Supabase SQL Editor 에서 `supabase_no_repeat.sql` **한 번** 실행 (실행 전에도 앱은 이 기기 기록으로 그대로 동작합니다).

`index.html` 한 파일로 도는 모바일 웹 앱입니다. 데이터는 **Supabase**(인증·프로필·호감·매칭·대화·인증심사·충전·신고)에 저장됩니다.

## 1. 처음 한 번만 — Supabase 준비

1. **스키마 실행** — Supabase 대시보드 → SQL Editor → New query →
   `supabase_schema.sql` **전체**를 붙여넣고 **RUN** (여러 번 실행해도 안전합니다).
   테이블 9개 + 운영 설정, RLS 정책, 서버 함수, 데모 프로필 6명이 만들어집니다.
2. **이메일 인증 끄기(권장)** — Authentication → Sign In / Providers → Email →
   *Confirm email* **OFF**. 끄면 가입 즉시 로그인됩니다.
   켜 둔 경우: Authentication → URL Configuration → **Site URL** 을
   `https://dpwl519-wq.github.io/990_mannam/` 로 바꾸고, 가입 후 메일의 인증 링크를 눌러야 로그인됩니다.
3. **운영자 PIN** — 기본값 `990418` (`admin_config` 테이블). 바꾸려면:
   ```sql
   update public.admin_config set admin_pin = '내PIN' where id = 1;
   ```
4. **입금 계좌** — 앱 → 운영자 → PIN 입력 → `입금 계좌 설정` 탭에서 저장하면
   사용자 충전 화면에 바로 표시됩니다.

## 2. 사용 흐름

1. 앱에서 회원가입(이메일·비밀번호·닉네임·성별·출생연도) → 매칭권 3장 지급
   - 닉네임은 `따뜻한 라떼`처럼 자동 제안되고, 옆의 ↻ 버튼으로 다시 뽑거나 직접 고칠 수 있어요.
   - 출생연도는 **1980~2004년** 콤보박스에서 고르고, 저장되는 `age`는 기존 프로필과 같게 `올해 − 출생연도`예요.
2. 첫 로그인 때 **프로필 등록** 화면으로 바로 이동합니다.
   사진 1장과 필수 항목(닉네임·나이·직업·지역·MBTI·키·한 줄 소개)을 채워 **맨 아래 `프로필 저장`** 을 누르면
   다른 화면(오늘의 인연·매칭·대화)이 열립니다. 빠진 항목은 화면 위 배너에 표시돼요.
3. 첫 로그인 때 **데모 인연**이 자동으로 채워집니다
   (받은 호감 2 · 매칭된 대화 1 · 심사 대기 인증 2 · 충전 요청 1 · 신고 1).
   실제 가입자가 늘면 운영자 콘솔 → `설정` → **데모 회원 노출**을 끄세요(모든 회원 화면에서 사라집니다).
4. **가입은 운영자 승인 후 입장** — 새로 가입한 회원은 `가입 승인 대기` 화면만 보고,
   운영자 콘솔 → **`가입 승인`** 탭에서 `승인`을 눌러야 오늘의 인연·매칭·대화가 열립니다.
   - 가입 상태(`profiles.status`): `pending`(대기) → `active`(입장) / `rejected`(반려).
   - 승인 전 회원은 다른 회원의 오늘의 인연에도 나오지 않습니다(`status = 'active'` 만 노출).
   - 기존에 활동하던 회원과 운영자 계정은 그대로 `active` 로 유지됩니다.
   - 켜는 방법: Supabase SQL Editor 에서 `supabase_signup_approval.sql` **한 번** 실행
   - 같은 방식으로 `supabase_no_repeat.sql` 도 **한 번** 실행하면 오늘의 두 장이 DB 기준으로 바뀝니다(중복 추천 영구 차단).
     (여러 번 실행해도 안전합니다 · `supabase_schema.sql` 에도 같은 내용이 들어 있어요).
5. 운영자 콘솔(PIN)에서 인증 승인 · 입금 확인(매칭권 지급) · 신고 정지를 처리합니다.
   - 로그인 화면 맨 아래 **운영자로 들어가기** → 운영자 이메일·비밀번호·PIN(`990418`)을 넣으면
     소개팅 프로필 없이 바로 운영자 콘솔이 열립니다. 계정이 없으면 **운영자 계정 만들기**로
     운영자 전용 계정을 만들 수 있어요(성별을 고르지 않아 인연 덱에는 나오지 않습니다).

## 3. 구조

| 파일 | 역할 |
| --- | --- |
| `index.html` | 화면 + 앱 로직 (Supabase JS v2 CDN, publishable 키만 사용) |
| `supabase_schema.sql` | 테이블 · RLS · 서버 함수 · 데모 시드 (idempotent) |
| `supabase_signup_approval.sql` | 가입 대기(pending) · 운영자 가입 승인만 따로 실행하는 증분 SQL (idempotent) |
| `supabase_no_repeat.sql` | 이미 본 상대 영구 차단(`seen_targets`) · 오늘의 두 장 DB 배정(`today_deck`) 증분 SQL (idempotent) |

- 매칭권 차감·48시간 자동 반환·매칭 성사·후기 300P·충전 승인은 모두 **서버 함수**(`send_like`, `expire_likes`, `submit_review`, `admin_review_charge` …)에서 원자적으로 처리됩니다.
- 매칭 우선순위는 **외모 · 직장 · 키 · 나이 · MBTI·성격 · 동네·거리 · 취미·가치관 · 비흡연·음주** 중 3개까지 고를 수 있어요(외모는 사진을 올린 프로필, 키는 178cm 이상, 나이는 선호 나이 기준).
- 지인 번호 차단은 **연락처에서 불러오기(Android Chrome)** · 직접 입력을 지원하고, 번호는 기기 안에서 해시로 바뀌어 저장됩니다(이름·원본 번호는 저장하지 않음).
- 앱에서 직접 바꿀 수 있는 프로필 열은 열 단위 권한으로 제한했습니다
  (`match_tickets`, `points`, `verified`, `height_verified`, `is_admin` 등은 앱에서 위조 불가).
- `email`, 차단 목록, 관리자 여부는 다른 사용자에게 노출되지 않습니다.
- 새 메시지·호감은 7초 주기로 다시 읽어 옵니다.

## 5. 취향 순위는 어떻게 쌓이나요

- 저장 위치는 **`profiles.priorities` (jsonb)** 하나입니다. 이미 쓰던 선호 조건 객체에 `taste` 키만 더합니다.
  ```json
  {
    "ageMin": 30, "ageMax": 40, "mbti": [], "priorities": ["job", "style"],
    "areas": ["서울시 전역"], "values": [],
    "taste": {
      "weights": { "job": 4, "hobby": 2 },
      "responds": { "job": { "accept": 2, "decline": 0 }, "hobby": { "accept": 1, "decline": 0 } },
      "actions": { "accept": 2, "decline": 0 },
      "updatedAt": "2026-11-19T08:00:00.000Z"
    }
  }
  ```
- 시작 점수는 **수동 1순위 5 · 2순위 3 · 3순위 2점**이고, 이 값은 저장하지 않고 계산할 때 더합니다(수동 순위를 다시 골라도 학습한 점수는 유지).
- 응답 사유로 고른 항목은 **수락 +2점 · 거절 +1점**씩 쌓입니다(`taste.weights`). 점수가 같은 항목은 수동 순위 → 화면 항목 순서로 정렬합니다.
- `taste.actions` 는 수락·거절을 누른 횟수(응답 건수)이고, `taste.responds` 는 항목별로 몇 번 골랐는지입니다. 내 프로필 카드에는 `응답 3건(수락 2 · 거절 1) · 고른 이유 5개`처럼 함께 보여 줍니다.
- 오늘의 인연 카드 점수(`compatibility`)는 상위 3개 항목 점수를 **비율(1순위 10점 기준)**로 환산해 더합니다. 그래서 순위가 뒤집히면 카드 순서도 따라 바뀝니다.
- `taste` 에는 **상대 id·날짜를 남기지 않습니다**. `profiles.priorities` 는 다른 회원도 읽는 열이라, 누구를 수락·거절했는지 남기지 않기 위해서입니다(항목별 누적 점수와 횟수만 저장).
- 데모 6명의 우선순위는 `index.html` 의 `DEMO_PRIORITIES` 예시 값입니다(SQL 재실행 없이 화면에 보이도록).
- `취향 데이터 초기화` 는 `taste` 만 지우고 수동 1·2·3순위는 그대로 둡니다. 수락/거절을 되돌리면(건너뛰기 되돌리기) 그때 쌓인 점수도 함께 되돌립니다.

## 6. 참고

- 결제는 **계좌이체/카카오페이 입금 확인형**입니다(자동 결제 아님). 회원이 입금자명을 남기면 운영자가 확인 후 매칭권을 지급합니다.
- 회사 메일 인증은 아직 화면 인증번호 방식이며 실제 메일 발송은 연결되어 있지 않습니다. 서류 인증은 운영자 심사로 처리됩니다.
- 회사명(`profiles.company`)은 직장인 인증 승인으로만 기록됩니다(승인 화면에서 운영자가 확인·수정). 앱에서는 입력할 수 없도록 열 단위 권한과 트리거로 막아 두었습니다.
- 키 인증이 승인되면 `profiles.height` 가 확인된 값으로 고정되고, 이후 본인은 바꿀 수 없습니다.
- 전화번호 차단은 해시 값만 저장하고 원본은 남기지 않습니다.
